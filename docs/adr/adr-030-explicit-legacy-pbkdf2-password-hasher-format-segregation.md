# ADR-030: Explicit Legacy PBKDF2 Password Hasher Format Segregation

## Status
Accepted

**Deciders**: EricksonLopez.Security Core Team

## Context

In [ADR-024](./adr-024-argon2id-hasher-implementation-strategy.md), the architectural strategy for password hashing documented that the v1.x `Argon2idPasswordHasher` utilized PBKDF2-HMAC-SHA512 (210,000+ rounds) as its computational substrate while formatting hashes with the `$argon2id$` modular crypt prefix for forward compatibility.

During the comprehensive security audit (`MEGA-AUDITORIA`), finding **SEC-005** raised an important architectural and compliance risk:
- When security scanners or auditors inspect `IPasswordHasher.Algorithm`, returning `PasswordHashAlgorithm.Argon2id` while executing PBKDF2-HMAC-SHA512 violates the principle of truth in cryptographic reporting.
- While PBKDF2-HMAC-SHA512 at 210,000 rounds satisfies NIST SP 800-63B and OWASP guidelines, it lacks memory-hardness against GPU-accelerated dictionary attacks.

---

## Decision

### 1. Introduce `LegacyPbkdf2PasswordHasher`
Introduce a dedicated hasher class `LegacyPbkdf2PasswordHasher` in `EricksonLopez.Security.Passwords`:
- **Native Format**: Hashes newly generated by this class use the explicit, truthful prefix `$legacy-pbkdf2$`.
- **Truthful Algorithm Reporting**: `Algorithm` property strictly returns `PasswordHashAlgorithm.Pbkdf2HmacSha512`.
- **Memory Hardness**: `IsMemoryHard` returns `false`, and `SubstrateDescription` explicitly states `"PBKDF2-HMAC-SHA512 (ADR-024)"`.

### 2. Backward-Compatible Verification & Transparent Rehash
- `LegacyPbkdf2PasswordHasher.VerifyPassword` parses and verifies both native `$legacy-pbkdf2$` and legacy `$argon2id$` formats.
- When an old `$argon2id$`-formatted hash is verified, `NeedsRehash` returns `true`, prompting `CompositePasswordHasher` to emit `PasswordVerificationResult.SuccessRehashNeeded`.
- This ensures zero-downtime, transparent migration to native formats on the user's next login without forced password resets.

### 3. DoS Protection (DOS-001)
During hash verification, iteration multipliers in the format header are strictly bounded by `MaxStoredTimeCost = 100` (limiting iterations to 7,000,000 rounds), preventing computational denial-of-service via forged iteration parameters.

---

## Consequences

- **Positive**:
  - Full adherence to cryptographic truthfulness and compliance standards.
  - Zero disruption or forced password resets for existing users with legacy hashes.
  - Transparent upgrade path to primary hashing algorithms via `CompositePasswordHasher`.
  - Built-in bounds against DoS via parameter manipulation.
- **Negative**:
  - Maintains dual prefix support (`$legacy-pbkdf2$` and `$argon2id$`) in legacy verification pathways.
